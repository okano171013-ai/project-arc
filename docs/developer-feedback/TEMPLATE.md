# Developer Feedback（AI開発日記）テンプレート

> Version完了時の必須成果物。機能一覧の再掲ではなく「なぜそうしたか」「次に何を警戒するか」を未来の担当者へ残す。

## メタデータ

- Version / 日付:
- 担当エンジン: Claude Code / Codex / その他
- Git commit / tag:
- 対応Issue / 関連Report:
- 状態: Draft / Complete / Reopened

## 1. 目的

解決したかった利用者課題と完了条件を3行以内で記載する。

## 2. 実装

- 追加・変更・削除した機能
- 主な変更モジュール
- 利用者から見たBefore / After

## 3. 設計判断

採用案、見送り案、境界・データモデル・API契約への影響。

## 4. 理由

判断の根拠、制約、トレードオフ。

## 5. 副作用

互換性、性能、セキュリティ、運用、データ、新たな保守コスト、回避策。

## 6. テスト

実行コマンドと結果、追加テスト、未実行の検証と理由、手動確認結果。

## 7. 未解決

Issue ID、Priority、再現条件、暫定対応、判断者。なければ「なし」。

## 8. 次Version

次の作業を依存関係と着手条件付きで最大5件。

## 9. Owner確認事項

費用、秘密情報、本番変更、外部公開、不可逆操作、Constitution / Principles変更。なければ「なし」。

## 10. 関連ADR

- 新規 / 更新 / 影響を受けるADR:
- ADR不要と判断した理由（該当時）:

## 完了宣言

- [ ] Report、Feedback、Roadmap、PM Status、Open Issuesが同じ事実を示す
- [ ] commit / tagを記録した
- [ ] 未実行テストを成功扱いしていない
- [ ] Owner確認事項を通常タスクへ埋没させていない
- [ ] 次担当者がこの文書だけで再開できる
