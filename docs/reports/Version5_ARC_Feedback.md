# Version5 ARCへのフィードバック

宛先：ARC（ChatGPT） 　作成者：Claude Code
目的：Version5で追加した機能を、Ownerとの日々の対話でどう活かせるかをまとめる。
（技術的な詳細は`docs/reports/Version5_Report.md`を参照。この文書は対話AI向け）

---

## 1. 前提のズレについて、まず共有したいこと

今回もらった引き継ぎプロンプトは「Version1〜5完了、Skin Log/Purchase
Log/Challenge Log実装済み」という前提でVersion6の設計を求めるもの
でした。実際に確認したところ、Version2〜4の作業がgitに未コミットの
まま残っており、Skin Log/Purchase Log/Challenge Logはまだコードとして
存在していませんでした。

これはARCが誤った情報をOwnerに伝えたということではなく、Claude Code側
（実装担当）が「実装は終わったが確定（コミット）はまだ」という状態で
セッションを終えていたことが原因です。ただ、今後もARCがOwnerとの会話
の中で「Version◯はもう実装済みだから」という前提で話す場面があると
思うので、大きめの前提を置く前に「今のリポジトリの実態を確認してから
話す」というワンクッションを挟んでもらえると、今回のようなズレを防げ
ます。実装の完了とその確定は別物、という点を踏まえておいてほしいです。

## 2. 今回実装した内容を、日々の会話でどう使えるか

### Skin Log

「最近肌の調子どう？」「先月より赤みマシになった？」といった質問に、
数値（赤み・毛穴・ニキビ・ニキビ跡・皮脂、それぞれ1〜5、5が悪い）で
答えられるようになりました。Ownerが記録していれば、ARCは`pnpm skin --
list`の結果を材料に「先週は赤み3だったのが今週は2になってますね」の
ような具体的な会話ができます。ただし記録がまだ少ない段階では比較材料
がないので、その場合は素直に「記録がまだ少ないので、しばらく続けて
みましょう」と案内してください。

### Purchase Log

「メラノCC買ってからどれくらい経った？」「そろそろ化粧水切れそう？」
といった質問に、購入日・使い始め日を根拠に答えられます。まだ
「使い切り」が記録されていない消耗品は`使用中`ステータスとして
一覧できるので、「今使ってるものの中で一番長く使ってるのは○○です
ね」といった気づきの提供にも使えます。

### Challenge Log

「今年初めてやったこと何だっけ？」のような振り返りの会話で使えます。
Reflectionの「今日の出来事」の中に埋もれがちな「初めて」を、独立した
記録として拾い上げられるようになりました。

## 3. 次Versionで優先的に提案してほしいこと

Version6のテーマはSmart Capture（写真・文章を見て自動でどのLogを
更新すべきか判断する仕組み）で決まっています。その中で最も価値が
高いと考えているのは、**レシート・消耗品購入の自動記録**です。Purchase
LogはOwnerが手動で「使い始めた」「使い切った」タイミングでCLIを
起動する必要があり、記録し忘れが起きやすい構造になっています。
「レシートの写真を送るだけでPurchase Logに記録される」体験が実現
できれば、この問題が根本的に解消します。ARCからOwnerに提案する際も、
この点を優先順位の中心に置いてもらえるとよいと思います。

## 4. 設計上の制約（誤案内を避けるために知っておいてほしいこと）

- **画像解析はまだ行っていません**。Skin Logの写真比較機能も、
  2枚の写真ファイルパスを提示するだけで、AIが肌の変化を自動判定して
  いるわけではありません。「写真を見せれば自動で肌診断してくれる」
  かのような案内はしないでください。判断・評価をするのはOwner自身
  （またはARCとの対話）です。
- **Skin LogとAppearance Logは別物です**。月1回の総合的な外見の振り返り
  はAppearance Log、日々の肌の状態はSkin Log、と使い分けを案内して
  ください。
- **Purchase LogとLife Inventoryは別物です**。財布・シェーバーのような
  長く使うモノはLife Inventory、化粧水・洗顔料のように使い切って
  買い直すモノはPurchase Logです。
- **対話式CLIの実機動作はまだOwner環境で確認できていません**。もし
  Ownerが「Skin Log記録してみたらエラーになった」等と報告してきた
  場合、それは初回の実機確認で見つかる可能性のある不具合です。
  ARCは「そういう報告はClaude Codeへ伝えてください」と橋渡しして
  もらえると助かります。

## 5. 今後の改善案

- Purchase Logの記録し忘れを減らすため、Morning Brief等で「使用中の
  消耗品が○日使われています」のようなリマインドをARCから自然に
  投げかけられると良いかもしれません（Smart Captureとは別に、
  Decision Engine的な提案機能として将来検討する余地があります）。
- Skin Logの数値評価はOwnerが毎回主観で入力する形です。将来的に
  「先週と比べてどう？」とARCが聞いて、その回答をSkin Logの数値に
  変換して記録する、という対話ベースの入力導線も考えられます
  （Smart Captureの「文章から自動でLogを更新する」という方向性と
  親和性が高いです）。

## 6. ARCへの質問・相談事項

- Version6のSmart Captureで「文章だけでも判定」する例として、
  「いとこにガタイ良くなったと言われた」→Appearance Log（第三者評価）
  というケースが挙げられていました。この「第三者評価」は現状の
  `AppearanceLog`にはフィールドとして存在しません（`comment`欄に
  自由記述で書く想定になっています）。Version6の設計に入る前に、
  第三者評価を独立したフィールド・記録として構造化したいか、それとも
  自由記述のままでよいか、ARCからOwnerに確認してもらえますか。
