# Version Report テンプレート

`docs/reports/VersionN_Report.md`を生成する際は、必ず以下の構成に従う。
Owner指示（Version3完了時に12章、Version4完了時に13章、Version9
完了時に14章を追加）により、12〜14章は全Versionで必須。

1. Version概要
2. 今回実装した機能（理由も含めて説明）
3. 実装しなかった機能（延期理由も記載）
4. Architecture Review（追加・変更したEntity/UseCase/Repository/Infrastructureの一覧）
5. ADR（追加・変更したADR、追加しなかった理由）
6. テスト（件数、カバレッジ、typecheck、lint、実機確認）
7. 修正したバグ（検出方法、原因、対応方法、再発防止）
8. 技術的負債（今後改善したい点）
9. 次Versionへの申し送り（技術的観点から推奨する事項）
10. POへの提案（提案・懸念点・改善案を自由に記載）
11. CEOへのコメント（今回の成果、次Versionへの期待）
12. **ARCへの引き継ぎ**（Owner追加指示、2026年7月）
13. **Product Review**（Owner追加指示、2026年7月）
14. **10年後のProject ARCへの貢献**（Owner追加指示、2026年7月、Version9より）

---

## 12章「ARCへの引き継ぎ」の書き方

Project ARCの人格（ARC自身）が、今Versionの内容を踏まえて次に
何を覚えておくべきかを引き継ぐ章。`docs/ai-roles.md`の責務分担に
基づき、Claude Codeが「実装した事実」を、ARCが「思考・対話・
優先順位提案」に使える形で要約する。以下4項目を必ず含める。

- **新しい資産**：今Versionで新たに使えるようになったデータ・
  機能・情報（例：Google Calendarの実データ、メンテナンス履歴等）。
  ARCが会話の中で参照・活用できるものを列挙する。
- **新しいルール**：今Versionで確立した設計上・運用上のルール
  （例：UIを変えずデータソースだけ差し替える、等）。ARCが今後
  提案する際に踏まえるべき制約。
- **新しい思想**：今Versionのテーマが Project ARC全体の思想
  （`docs/vision.md`, `docs/principles.md`）にどう接続したか。
- **Ownerについて分かったこと**：実装・実機確認のやり取りを通じて
  観察された、Ownerの作業スタイルや反応（事実ベースで記述し、
  性格の断定的な評価はしない。Principle 5: 推測は推測として扱う）。

## 13章「Product Review」の書き方

技術的な達成（1〜12章）とは切り離し、**Ownerの体験がどう変わったか**
だけに焦点を当てる章。CTOではなくPO視点で書く。以下4項目を必ず含める。

- **ユーザー体験で改善されたこと**：Before/Afterの形で、今Versionで
  Ownerが日常的に得られる価値を具体的に記載する。
- **毎日使う理由**：Morning Brief / Reflection / Inventory等、既存の
  毎日使う機能群が今Versionでどう強化されたか。
- **懸念**：UX上、まだ改善の余地がある点を率直に書く（技術的負債とは
  区別し、「使っていて気になる体験」に絞る）。
- **次Versionで最も価値が高い改善**：POへの提案として、機能の網羅性
  ではなく体験価値の観点から1つに絞って提案する。

## 14章「10年後のProject ARCへの貢献」の書き方

Project ARCが「機能開発」ではなくプラットフォーム開発に近づいている
という認識（Version9、ARCブリーフ）に基づき、短期的な機能価値
（13章）とは別に、長期的な設計価値を毎回言語化する章。以下を含める。

- 今Versionの実装が、10年後も使われ続けるとしたら、どの設計判断が
  効いてくるか（あるいは、どの判断が見直しを要するか）。
- 「人生OS」というVisionから逆算したとき、今Versionはどこに位置する
  石（土台・接続点・拡張点等）だったか。
- 機能数や見た目の派手さではなく、構造的な一貫性・拡張性の観点で
  評価する（Principle 8: 長期保守性と直結）。

短くてよい（他章より簡潔に、3〜5段落程度を目安とする）。ロードマップ
全体の一貫性を保つための「立ち止まって考える」章であり、詳細な
技術解説は他章に譲る。
