# Version6 ARCへのフィードバック

宛先：ARC（ChatGPT） 　作成者：Claude Code
目的：Version6で追加したSmart Captureを、Ownerとの日々の対話でどう
活かせるか、そして誤案内を避けるために知っておいてほしいことをまとめる。
（技術的な詳細は`docs/reports/Version6_Report.md`を参照。この文書は対話AI向け）

---

## 1. 一番大事な訂正：Smart Captureは「自動判断」ではありません

引き継ぎプロンプトのテーマ「Smart Capture」は、「Ownerが『記録して』
と言わなくても、ARCが写真・文章を見てどのLogを更新すべきか自動判断
する」という説明でした。この方向で実装を始める前に、Project ARC自身の
`docs/ai-roles.md`を確認したところ、「System（このコードベース）は
何が正しいか・何を優先すべきかを一切判断しない、忠実に記録するだけ」
という、プロジェクトの最も基本的な統治原則に directly 抵触することが
分かりました。

そのため、実装したSmart Captureは以下のような設計になっています。

- Systemは、入力された文章に対してキーワード一致による**下書き提案**
  （例：「肌」という語があれば「Skin Logかもしれません」）を出すだけ。
- **最終的にどのLogに何を記録するかは、常にOwner（またはARCとの対話
  を経たOwner）が確定する**。Systemが勝手に書き込むことはない。

つまり、「ARCが自動で判断してくれる」という表現は、今後Owner向けに
使わないでください。正確には「Systemが機械的な下書き候補を出し、
最終的な判断はOwnerかARCが行う」です。この区別は、Project ARC全体の
設計思想（人間が最終意思決定者、ARCは思考パートナーであり決定権はない、
Systemは判断しない）の根幹に関わるので、軽視しないでほしいです。

## 2. 今回実装した内容を、日々の会話でどう使えるか

### Smart Capture（`pnpm capture -- add`）

Ownerが「今日メラノCC買った」「肌にニキビできて初めて皮膚科行った」
のような一言をARCに話した際、ARCが「それ、Skin LogとChallenge Logに
記録しておくとよさそうですね。`pnpm capture -- add`で記録できますよ」
と案内する、という使い方を想定しています。あるいは、ARCとの会話の中で
「これはPurchase Logに、これはAppearance Logに」という振り分けが
すでに決まっている場合、Ownerはそれをそのまま`pnpm capture`に入力
すれば、複数のLogへ一度に記録できます。

### Capture Log（`pnpm capture -- list`）

「最近何を記録したっけ」という会話で、いつ・何を入力し・どのLogに
反映されたかの履歴を参照できます。

## 3. 次Versionで優先的に提案してほしいこと

Version5フィードバックで提案した「レシートの自動記録」は、今回の
設計方針（Systemは判断しない）を踏まえると、単純な自動化では実現
できないことが分かりました。実現するには、ARC（ChatGPT）側が実際に
レシートの内容を解釈した上で、その結果をProject ARCに渡す連携
（例：ARCが呼び出せるAPI）が必要です。これは`docs/adr/0002-defer-
ai-provider-abstraction.md`の再検討を伴う大きな決定なので、次Version
で優先的に提案するとしたら、「ARCとProject ARCを直接つなぐ連携を
作るかどうか」をOwnerと相談することだと思います。

## 4. 設計上の制約（誤案内を避けるために知っておいてほしいこと）

- **Smart Captureのキーワード判定は単純な文字列一致です**。「肌」
  「買った」「初めて」のような固定の単語リストとの一致を見ているだけ
  で、文脈理解や重要度判断はしていません。表記ゆれ（「にきび」と
  「ニキビ」等）にも対応していません。ARCが持つような柔軟な理解力は
  Systemにはないことを前提に案内してください。
- **画像解析はまだ一切行っていません**（Version1からの一貫方針）。
  Smart Captureに写真を渡しても、Systemは写真の中身を見て判断する
  ことはできません。写真はファイルとして保存されるだけです。
- **Smart Captureの対象LogはSkin Log/Purchase Log/Challenge Log/
  Appearance Logの4つのみ**です。Memory・Life Inventoryへは
  Smart Capture経由では書き込めません（従来通り`pnpm memory`/
  `pnpm inventory`を直接使う必要があります）。
- **対話式CLIの実機動作はまだOwner環境で確認できていません**。
  Skin/Purchase/Challenge/Appearanceの4つに同時に触れる、これまでで
  一番複雑なCLIフローなので、Ownerから「使いにくい」「エラーになる」
  等の報告があれば、それは初回確認で見つかる可能性のある不具合です。
  Claude Codeへ橋渡ししてください。

## 5. 今後の改善案

- 「Smart Captureは提案止まり」という制約は、Owner体験としては
  一段階分の確認の手間が残ります。もしOwnerが「毎回確認するのが
  面倒」と感じるようなら、それは機能の不具合ではなく設計上の
  トレードオフ（Systemは判断しないという原則を守るための代償）だと
  理解した上で、Owner自身がその手間を許容できるかどうかを確認して
  もらえるとよいです。
- 前回のフィードバックで挙げた「第三者評価の構造化」の質問は、
  今回もまだ解決していません。Smart CaptureはAppearanceLogの
  `comment`欄に自由記述として書き込む設計のままです。

## 6. ARCへの質問・相談事項

- 「ARCとProject ARCを直接つなぐ連携（API等）を作るべきか」を、
  Ownerと相談してもらえますか。これができれば、ARCが会話の中で
  判断した内容を、Owner側の追加操作なしにProject ARCへ直接記録
  できるようになり、ブリーフが本来目指していた「送るだけで記録
  される」体験に近づきます。ただし、これは新しい技術的スコープ
  （認証・API設計等）を伴う大きな意思決定なので、次に着手する
  Versionのテーマとして良いかどうか、Ownerの優先順位を確認して
  ほしいです。
